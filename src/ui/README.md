# UI

## Overview

The `ui` module is responsible for rendering application views and managing reusable interface behavior.

It contains:

- Project and task renderers
- Loading, error, and empty states
- Modal behavior and accessibility
- Confirmation dialogs
- Button loading states

The UI layer reads application state and receives data from the application flow, but does not perform API requests directly.

## How It Connects

```text
State / Services
       ↓
   main.js
       ↓
      UI
       ↓
     DOM
```

User actions generated by the UI are handled by the forms/controllers layer.

## Key Components

### `layoutRenderer.js`

Builds the selected-project dashboard.

#### `renderProjectDetails(project)`

Renders:

- Project overview
- Project status and priority
- Project metadata
- Task section
- Task status/priority filters
- Add Task action

---

### `projectRenderer.js`

Renders the project navigation in the sidebar.

#### `renderProjects(projects, selectedProjectId, onProjectSelect)`

Displays the visible projects, selected-project state, project count, and the empty-project state.

Project names are passed through `escapeHtml()` before being inserted with `innerHTML`.

---

### `taskRenderer.js`

Renders tasks belonging to the selected project.

#### `renderTasks(tasks, options)`

Renders task cards and distinguishes between:

- No tasks
- No tasks matching the active filters
- Normal task results

Task information is escaped before being inserted into HTML.

#### `initializeTaskAccordion()`

Provides keyboard-accessible native-button task expansion/collapse behavior and keeps `aria-expanded`, the hidden details section, and the visual expanded state synchronized.

---

## Application States

### `loadingStateRenderer.js`

#### `renderLoadingState()`

Displays a loading message while workspace data is being fetched.

Uses `role="status"`, `aria-live="polite"`, and `aria-busy="true"` to communicate the state to assistive technologies.

### `errorStateRenderer.js`

#### `renderErrorState(errorMessage)`

Displays a workspace loading error using `role="alert"`.

The error message is escaped before being inserted into HTML.

### `emptyStateRenderer.js`

#### `renderNoProjectsState()`

Displays the initial empty-workspace message when no projects are available.

---

## Modal Management

### `modal.js`

Provides reusable modal behavior.

#### `openModal(modalId)`

- Shows the modal.
- Stores the previously focused element.
- Moves focus into the modal.
- Prevents the hidden dialog from remaining interactive.

#### `closeModal(modalId)`

- Hides the modal.
- Clears modal state.
- Restores focus to the element that opened it when possible.

#### `initializeModal(modalId)`

Adds:

- Backdrop-click closing
- Escape-key closing
- Keyboard focus trapping

This provides the core accessibility behavior for the application's dialogs.

#### `bindModalButtons()`

Connects modal open/close controls and the Add Task action to the appropriate modal.

---

### `confirmModal.js`

Provides the reusable delete-confirmation dialog.

#### `showConfirmation(options)`

Updates the confirmation title, message, confirm button text, and callback before opening the confirmation modal.

The confirmation action uses the shared button-loading component while the asynchronous operation is running.

---

### `buttonLoading.js`

Provides reusable loading behavior for buttons.

#### `setButtonLoading(button, loadingText)`

Stores the original button text, replaces it with loading text, disables the button, and applies the loading class.

#### `resetButton(button)`

Restores the original text and re-enables the button.

---

## Accessibility Highlights

The UI layer includes several accessibility fundamentals:

- Semantic `section`, `header`, `nav`, `dl`, `dt`, and `dd` elements.
- Native `<button>`, `<input>`, `<select>`, and `<textarea>` controls.
- Visible labels for form/filter controls.
- `aria-label` and `aria-labelledby` where appropriate.
- `aria-expanded` and `aria-controls` for task accordions.
- `aria-current` for the selected project.
- Live regions for loading/task updates.
- Alert semantics for loading errors.
- Escape-key modal closing.
- Focus trapping inside dialogs.
